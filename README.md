## Встановлення

Потрібен Python 3.10 або новіший.

```bash
git clone https://github.com/mariiakovalets/sipl-formal.git
cd sipl-formal
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

На Windows замість `source .venv/bin/activate` — `.venv\Scripts\activate`.

Перевірити, що все встановилось:

```bash
pytest
sipl-formal --help
```

## Формат граматики

Текстовий файл, одне правило (з альтернативами) на рядок, перша ліва частина — аксіома:

```
# варіант 3 практичної роботи 4
S -> AbBC | ADcBC | ADCC | ACc
C -> eps | bCc
A -> eps | aA
B -> eps | bB
D -> dD
```

- Стрілка: `->`, `→` або `::=`. Порожній ланцюжок: `ε` або `eps`. Коментар: `#`.
- Нетермінал — велика латинська літера, за якою можуть іти цифри чи штрихи: `S`, `A′`, `A'`, `Z12`.
- Будь-який інший символ — термінал (один символ). Пробіли лише розділяють символи: `A 1` — це A і термінал 1.
- Ліва частина має бути одним нетерміналом (КВ-граматика), інакше буде помилка з номером рядка.

Приклади: `examples/grammars/`.

## Команди

### FORM-01: нормальна форма Хомського — `cnf`

```bash
sipl-formal cnf examples/grammars/pr4_variant3.cfg
sipl-formal cnf examples/grammars/pr4_variant3.cfg --epsilon-free   # зупинитись на формі без ε-правил
sipl-formal cnf examples/grammars/parentheses.cfg --json
```

Кроки (як у практичній роботі 4): непродуктивні нетермінали (Pr0, Pr1, …) → недосяжні (R0, R1, …) →
ε-правила (якщо ε належить мові, вводиться нова аксіома S′ → S | ε) → ланцюгові правила A → B →
заміна терміналів у довгих правилах (A′ → a) → розбиття правил довжини > 2 (однакові «хвости» отримують
один нетермінал). Для кожного кроку друкується, які правила додано й видалено.

Перевірка в тестах: результат має вигляд A → BC | a (і S → ε лише для аксіоми), а мова збігається з вихідною
на всіх словах довжини ≤ 7 (найменша нерухома точка для вихідної граматики проти алгоритму CYK для результату).

### FORM-02: рівняння над мовами — `equations`

```bash
sipl-formal equations examples/grammars/pr5_variant9.cfg --max-len 14
```

```
Система рівнянь:
S = {a}A{cc}
A = {ee}A{d} ∪ {b}

Наближення (слова довжини ≤ 14):
S0 = ∅, A0 = ∅
S1 = ∅, A1 = {b}
S2 = {abcc}, A2 = {b, eebd}
...
Збігається з мовою граматики на словах довжини ≤ 14.
```

Кожен нетермінал стає змінною, кожне правило — доданком об'єднання, послідовності терміналів — мовами-константами.
Розв'язок шукається послідовними наближеннями X0 = ∅, X(k+1) = φ(Xk). Зберігаються лише слова довжини ≤ max-len,
тому на цій межі наближення завжди стабілізуються. Результат порівнюється з мовою, знайденою іншим способом:
пошуком виводів у формі граматики без ε-правил.

### FORM-03: лема про накачку — `pump`

Мова записується шаблоном з одним n, наприклад `a e^{2n} b^n d^n c^{2n}`. Показник може бути `n`, `2n`, `{3n+1}` або просто числом.

Програма бере одне слово мови і число k з леми та пробує всі способи розрізати слово на u, t1, x, t2, v так,
як вимагає лема: t1t2 не порожнє, а t1xt2 не довше за k. Для кожного розрізу t1 і t2 повторюються 0, 1, 2 і 3 рази,
і програма перевіряє, чи вийшло слово мови. Розріз показується як `u[t1]x[t2]v`, під ним — отримані слова з позначкою ∈ L або ∉ L.

```bash
sipl-formal pump "a e^{2n} b^n d^n c^{2n}" --k 4 --n 4
```

Щоб подивитися один конкретний розріз, задайте довжини u, t1, x, t2:

```bash
sipl-formal pump "a^n b^n" --k 3 --n 2 --split 1,1,0,1
```

Це навчальний асистент, а не вирішувач. Якщо жоден розріз не підходить, лема для цього слова і цього k не виконується,
але це ще не доведення, що мова не КВ: доведення має працювати для будь-якого k.

### FORM-04: виводи й дерева — `derive`

```bash
sipl-formal derive examples/grammars/arithmetic_ambiguous.cfg "x+x*x"
sipl-formal derive examples/grammars/arithmetic_ambiguous.cfg "x+x*x" --format dot > trees.dot
sipl-formal derive examples/grammars/anbn.cfg aabb --format json
```

Пошук у ширину лівосторонніх виводів (не більше `--depth` кроків, не більше `--limit` виводів).
Для кожного знайденого виводу будується дерево, з нього — правосторонній вивід. Якщо знайдено ≥ 2 дерева,
граматика неоднозначна. Відповідь чесно каже, чи пошук пройшов до кінця в межах глибини.

### CORE-01 і VIS-01: SIPL — `sipl-check`, `sipl-tree`

```bash
sipl-formal sipl-check examples/sipl/valid/power.sipl
sipl-formal sipl-check examples/sipl/invalid/missing_semicolon.sipl
#   помилка: рядок 3, стовпчик 3: неочікуване «Y», очікувалось: *, +, -, ;, end
sipl-formal sipl-tree examples/sipl/valid/power.sipl
sipl-formal sipl-tree examples/sipl/valid/power.sipl --format dot > power.dot
dot -Tsvg power.dot -o power.svg   # якщо встановлено Graphviz
```

Граматика: `src/sipl_formal/sipl/sipl.lark`. Вона задає ту саму мову, що й БНФ з практичної роботи 1:

```
P ::= begin S end
S ::= x := a | S1 ; S2 | if b then S1 else S2 | while b do S | begin S end | skip
a ::= n | x | a1 + a2 | a1 - a2 | a1 * a2 | (a)
b ::= a1 = a2 | a1 > a2 | b1 ∨ b2 | ¬b | (b)
```

БНФ курсу неоднозначна (x + y * z, S1 ; S2 ; S3), тому пріоритети записані додатковими рівнями:
`*` раніше за `+` і `-`, `¬` раніше за `∨`, цикл і розгалуження зв'язують сильніше за `;`, бінарні операції
групуються зліва. Вузли дерева підписані категоріями курсу (`<програма>`, `<оператор>`, `<вираз>`,
`<умова>`, `<змінна>`, `<число>`), кожен вузол має позицію (рядок:стовпчик) і фрагмент вихідного тексту.
`∨`/`or` і `¬`/`not` рівнозначні.

Приклади: `examples/sipl/valid/` (12) і `examples/sipl/invalid/` (12).

## Архітектура

```
src/sipl_formal/
├── grammar.py      модель КВ-граматики і текстовий формат        (спільне для FORM-01…04)
├── normal_form.py  FORM-01: кроки перетворень, кожен повертає Step з поясненням
├── cyk.py          перевірка належності слова для граматики в нормальній формі Хомського
├── bounded.py      мови на словах обмеженої довжини (для порівнянь і тестів)
├── equations.py    FORM-02: система рівнянь, наближення, порівняння
├── pumping.py      FORM-03: мови-шаблони, розклади, накачка
├── derivation.py   FORM-04: виводи, дерева, експорт
├── sipl/           CORE-01 + VIS-01: sipl.lark і parse_tree.py
└── cli.py          командний рядок
```

Дані проходять так: текст граматики → `Grammar` → перетворення / рівняння / пошук виводів → текст, JSON або DOT.
Для SIPL: текст програми → Lark (LALR) → `ParseNode` з позиціями → текст, JSON або DOT.
Кожен модуль можна використовувати як бібліотеку, CLI лише викликає їх.

Коди завершення CLI: `0` — успіх, `1` — помилка у вхідних даних (граматика, шаблон, програма, файл),
`2` — неправильні аргументи команди. Повідомлення про помилки йдуть у stderr.

## Обмеження

- Термінали граматик — по одному символу.
- FORM-02 і перевірки мов працюють на словах обмеженої довжини (`--max-len`), а не з нескінченними мовами.
- FORM-03 підтримує лише мови-шаблони з одним параметром n і блоками з однієї літери.
- FORM-04 шукає виводи в межах заданої глибини, тому для неоднозначності «не знайдено» означає «не знайдено в межах».
- SIPL: числа невід'ємні (−1 записується як `0 - 1`); `div` і `mod` з варіантів практичних робіт у БНФ курсу немає,
  тому вони не підтримуються.
